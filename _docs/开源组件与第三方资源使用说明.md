# LabGuard AI 开源组件、第三方模型、外部 API 与数据集使用说明

> 对应代码版本：`main` 分支 `aa9ab12`。

---

## 1. 总结

| 类别 | 是否使用 | 说明 |
| --- | --- | --- |
| 开源组件 | **是** | 运行时依赖 42 个 JAR，其中 37 个 Apache-2.0；测试依赖仅 test 作用域，不打入发布包 |
| 第三方模型 | **仅以 API 方式接入，不自研、不微调、不内置权重** | 默认 `demo` 模式**完全不调用任何模型**；`real` 模式对接兼容 OpenAI Chat Completions 协议的多模态模型 |
| 外部 API | **1 类**（视觉推理，可选开启） | `POST {VISION_API_BASE_URL}/chat/completions`；除此之外全站无任何第三方 HTTP 请求 |
| 公开数据集 | **否** | 未使用任何外部数据集，无训练环节；演示内容为团队手写的固定样例，页面数据来自使用者自行上传 |
| 前端第三方库 / CDN / 统计脚本 | **否** | CSS/JS/SVG 全部手写，模板与静态资源中无外链、无 `@import`、无 CDN 引用 |
| 自行分发的第三方二进制 | **否** | 发布包只含本项目 JAR（Spring Boot 可执行格式，依赖内嵌于 `BOOT-INF/lib/`）、脚本与文档 |

**合规结论**：默认交付形态（`VISION_MODE=demo`，即 JAR、Docker 镜像与发布包的默认值）在离线环境下即可完整运行，
不产生任何对外网络请求、不需要任何第三方账号或密钥，因此**不存在第三方条款被默认触发的情形**。

## 3. 第三方模型使用说明

1. **本项目不包含、不训练、不微调任何模型。** 代码仓库与发布包内均无模型权重文件（`.onnx`/`.safetensors`/`.bin`/`.tflite` 等一律不存在），
   无向量化中间产物，无推理引擎（ONNX Runtime / DJL / TensorFlow Java 等均未引入）。
2. **视觉能力的实现方式是"外部 API 集成"**：接口 `AiVisionService` 有两个实现，
   业务层只依赖接口，通过环境变量 `VISION_MODE` 切换：
   - `DemoAiVisionService`（默认）：**不读取图片内容、不发起任何网络请求**，返回团队手写的固定样例，
     结果来源恒为 `AiResultSource.DEMO`，页面同时显示"演示数据：未调用真实视觉 API"；
     复查场景固定返回 `INCONCLUSIVE`，绝不伪装成通过。
   - `RealAiVisionService`：把图片交给**第三方多模态大模型**判断，本项目自身不做任何图像识别算法。
3. **模型名称不由本项目固定**。`VISION_MODEL` 为必填配置项，由部署者按其选定的服务商填写；
   `.env.example` 中该项默认为空。截至本文撰写时，团队**尚未选定具体服务商与模型，也未配置密钥**，
   因此**不存在"已接通某真实模型"的事实**，代码中亦无任何厂商名称硬编码。
   （`_docs/成员A-视觉AI配置与API契约说明.md` 第 1.2 节的选型表仍为"待团队选定"，并有验收红线：
   未同时确定服务商、密钥、模型三项前不得声称真实 API 已接通。）
4. **提示词（Prompt）为本项目自研**，位于 `RealAiVisionService` 的 `SYSTEM_PROMPT` 与 `REVIEW_SYSTEM_PROMPT` 常量，
   仅描述输出 JSON 契约与核验边界，不含任何第三方模型的专有指令模板拷贝。请求固定 `temperature=0`。
5. **使用条款责任划分**：接入服务商时，模型的使用条款、内容政策与商用限制由**部署者自行遵守**；
   本项目仅做协议适配与结果校验，不重新分发模型、不转售模型能力、不以本项目名义为模型背书。
6. **结论边界**：无论使用何种模型，AI 输出在本系统中都被定义为**辅助建议**——`needsHumanReview` 在复查场景恒为 `true`，
   低置信度（默认阈值 0.6）强制转人工，工单关闭必须由人工执行，模型不具备自动闭环权限。

## 4. 外部 API 使用说明

### 4.1 唯一的外部调用点

| 项 | 内容 |
| --- | --- |
| 协议 | OpenAI 兼容的 Chat Completions（`POST`） |
| 端点 | `{VISION_API_BASE_URL}/chat/completions`；若已含 `/chat/completions` 则不重复拼接 |
| 鉴权 | 请求头 `Authorization: Bearer ${VISION_API_KEY}` |
| 客户端 | JDK 内置 `java.net.http.HttpClient`（**未引入 OkHttp / WebClient / OpenAI SDK 等第三方 HTTP 库**） |
| 超时 | 连接 5s、读取 30s（可由 `VISION_CONNECT_TIMEOUT` / `VISION_READ_TIMEOUT` 覆盖） |
| 请求体 | `model` + `temperature=0` + system/user 消息；图片以 **Base64 Data URL** 内嵌于 `content` 的 `image_url` 部分 |
| 图片约束 | 仅 JPG/JPEG/PNG，单张不超过 10MB（`ImageInput` 校验，页面端另有 5MB 预校验），超限在发送前拒绝 |
| 触发条件 | **仅当 `VISION_MODE=real` 且三项配置齐全**；否则不会发出请求 |
| 默认状态 | `demo`（JAR 的 `application.properties`、`.env.example`、`Dockerfile` 三处默认值一致）——**默认零外部调用** |

除上述端点外，应用运行时不访问任何外部地址：无遥测、无统计、无广告、无 CDN、无社交登录、无更新检查。

### 4.2 数据流向与隐私

- **发送内容**：使用者上传的现场照片（Base64）+ 本项目自研提示词 + 隐患上下文文本。照片以数据 URL 直发服务商，
  不经本项目服务器中转存储副本，也不上传到本项目控制的其他地址。
- **服务端留存**：取决于所选服务商的隐私政策，本项目无法控制，故部署者需自行确认服务商是否符合实验室数据合规要求；
  面向敏感场景（人脸、铭牌、危化品标识可反推实验室身份）建议优先使用私有化部署或国内合规节点。
- **密钥处理**：`VISION_API_KEY` 只来自操作系统环境变量或本地 `.env`（后者已被 `.gitignore` 忽略，且不随发布包分发）；
  **不写入数据库、不写入日志**。已逐行核查 `RealAiVisionService` 的 4 处日志语句，输出内容仅为
  endpoint、HTTP 状态码、模型名与异常类型，不含密钥、不含请求体、不含图片内容。
- **本地留存**：运行产生的数据只有 `data/labguard.db`（SQLite）与 `uploads/`（原图），二者均不进入 Git 仓库、不进入发布包。

### 4.3 失败处理

配置缺失 → `NOT_CONFIGURED`（HTTP 请求数为 0）；401/403 → `AUTH_FAILED`；429 → `RATE_LIMITED`；
5xx → `SERVER_ERROR`；超时 → `TIMEOUT`；连接失败 → `NETWORK_ERROR`；响应非法 → `INVALID_RESPONSE`。
所有失败以结构化异常上抛并显示给用户，**绝不回退到演示数据**，也绝不生成"看起来成功"的结果。
响应体由 `AiVisionResponseParser` 严格校验字段与取值域后才落库。

### 4.4 测试不访问外网

视觉模块用例（A-01~A-20）使用 **JDK 自带的 `com.sun.net.httpserver.HttpServer`** 在 127.0.0.1 上
模拟服务商响应，不调用任何外部 API、不需要真实密钥；`mvn test` 可在完全离线环境执行。

### 4.5 其他外部服务

| 类型 | 是否使用 |
| --- | --- |
| 地图 / 定位 / 天气 / 短信 / 邮件 / 支付 | 否 |
| 对象存储 / CDN | 否（图片存本地 `uploads/`） |
| 在线部署平台 | 可选，评委按 `DEPLOY.md`《Docker 部署》自行选择；项目本身不绑定任何平台 |

## 5. 数据集使用说明

1. **未使用任何外部数据集**：无图像数据集、无标注数据、无预训练语料，也不涉及模型训练/微调，
   因此不存在数据集许可证（如 CC 系列、ImageNet 学术许可、内部保密条款）的引用与合规问题。
2. **演示样例为团队原创**：`DemoAiVisionService` 中的固定隐患条目（"通道疑似被物品阻挡（演示样例）"等文本）
   由本项目手工编写，其证据描述字段本身即明确写出"这是固定的演示数据，未调用真实视觉 API，不代表系统分析了上传图片"。
3. **无内置种子数据**：`src/main/resources/schema.sql` 只包含 5 张表（`inspection` / `hazard` / `work_order` /
   `audit_event` / `ai_review`）的 `CREATE TABLE` 语句，经检索**不含任何 `INSERT`**，首次启动得到的是空库。
4. **页面数据全部来自使用者运行时录入**：巡检照片、隐患位置、整改说明等内容均由演示者当场上传/填写。
5. **不含真实实验室照片的分发**：开发调试期产生的图片保存在本地 `uploads/`，该目录已被 `.gitignore` 忽略，
   未进入 GitHub 仓库；发布包 `LabGuard-AI-v1.0.0.zip` 内 `uploads/` 与 `data/` 各只有一枚空占位文件
   （`.keep`，38 / 41 字节），已逐条目审计确认**无 `.env`、无 `labguard.db`、无 jpg/png 图片、无 API 密钥**。
