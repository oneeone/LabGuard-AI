# C 模块演示步骤（LabGuard AI）

面向比赛现场演示：从上传一张实验室照片开始，走到工单关闭的完整闭环。
全程使用 `demo` 模式，不依赖外网与真实视觉 API。

## 一、演示前准备

### 1. 启动

```bash
mvn package -Dmaven.test.skip=true
java -jar target\labguard-ai-0.1.0-SNAPSHOT.jar
```

浏览器打开 <http://localhost:8080> ，会自动跳转到「新建巡检」页。

### 2. 运行参数（均为可选）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8080` | 服务端口，被占用时改这里 |
| `VISION_MODE` | `demo` | `demo` 用固定样例，不调外部 API；`real` 调真实视觉 API |
| `VISION_API_BASE_URL` / `VISION_API_KEY` / `VISION_MODEL` | 空 | `real` 模式必填，缺失时页面会提示「视觉 API 未配置完整」，不会伪造结果 |

### 3. 演示数据

- 数据库：`data/labguard.db`（SQLite，启动时自动建表）
- 图片：`uploads/`（巡检原图与整改后照片，页面通过 `/uploads/...` 访问）
- 从干净数据开始：停止应用 → 删除 `data/labguard.db` → 重启
- 准备两张照片：一张巡检原图、一张整改后照片（JPG 或 PNG，各不超过 5MB）

### 4. 现场注意

- 浏览器窗口宽度建议 ≥ 1200px，窄屏（< 720px）会切成单列布局
- 上传后按钮会变成「AI 分析中…」并置灰，属于防重复提交设计，不是卡死

## 二、主线演示（约 7 分钟）

| # | 操作 | 讲什么 | 预期现象 |
|---|---|---|---|
| 1 | 打开首页 | 系统只有一个入口：先有巡检，才有工单 | 自动跳到 `/inspections/new` |
| 2 | 填写实验室名称、巡检人、巡检时间、备注，选择巡检照片 | 现场照片是唯一证据来源，AI 只做初筛 | 选好文件后文件名带大小回显 |
| 3 | 点「提交并开始 AI 分析」 | 提交即触发分析，期间按钮禁用 | 按钮文案变「AI 分析中…」，随后跳转分析结果页 |
| 4 | 讲解分析结果页 | 顶部标识数据来源；类别、位置、可见证据、置信度、建议措施逐项说明；置信度只是模型自评，不作为定级依据 | 顶部显示「演示数据，非真实识别结果」；风险卡片含「此结果需人工现场核实，请勿直接作为安全结论」 |
| 5 | 点「确认风险」 | AI 结果必须经人工确认才能进入整改流程 | 确认进度变「待确认 0 / 已确认 1」，卡片下方出现「创建整改工单」 |
| 6 | 点「创建整改工单」 | 同一隐患只允许一张工单，截止日期不能早于今天 | 表单顶部显示关联隐患摘要；创建后跳转 `/workorders/{id}`，提示「整改工单已创建，请按截止日期完成整改」 |
| 7 | 在工单详情填整改说明 + 上传整改后照片，提交 | 整改必须有说明 + 照片双证据，提交后进入待复查 | 状态变「待复查」，左侧巡检原图与右侧整改后照片并排展示，整改说明与提交时间可见 |
| 8 | 选择「复查通过，关闭工单」并提交 | 复查人对照前后照片核实，通过即闭环 | 状态变「已关闭」，复查记录显示结论、时间、复查人、意见；页面上不再有任何提交表单 |
| 9 | 向下滚动到「处理时间线」 | 每次操作都落库为审计事件，页面可回溯 | 依次列出创建、提交整改、复查通过（含状态变化、操作人、时间）；整改事件会带上当次整改说明 |
| 10 | 打开「整改工单」列表，切换「全部 / 待整改 / 待复查 / 已关闭」 | 工单是可跟踪的看板，不是一次性记录 | 每条工单显示类别、等级、实验室、责任人、截止日期、状态 |

## 三、可选分支（每个约 30 秒，时间充裕时演示）

### A. 退回整改（体现闭环可回退）

1. 新工单进入「待复查」
2. 选择「退回整改」但不填复查意见 → 页面提示「退回整改时必须填写复查意见」
3. 补填意见后提交 → 工单回到「待整改」，责任人可再次提交整改
4. 再次提交后看底部「处理时间线」→ 两次整改说明都在，右栏只显示最新一次，历史不丢

### B. 驳回风险（体现人工否决权）

1. 分析结果页展开「驳回此结果」
2. 不填理由直接提交 → 提示驳回理由必填
3. 填写理由后驳回 → 状态变「已驳回」，只能「重新上传图片」

### C. 上传校验（体现前端与服务端双校验）

| 输入 | 预期提示 |
|---|---|
| 不选文件 | 请选择图片：仅支持 JPG / PNG，且大小不超过 5MB |
| 上传 `.pdf` / `.txt` | 仅支持 JPG 或 PNG |
| 上传 6MB 图片 | 图片大小不能超过 5MB |
| 实验室名称留空 | 字段级报错，已填的巡检人与备注仍然保留 |

### D. 防跳步与异常页

- 已关闭工单的详情页没有任何提交入口（整改、复查表单都不渲染）
- 访问不存在的工单 `/workorders/999` → 自定义 404 页，提供返回列表与新建巡检入口
- 筛选参数非法（如 `?status=BAD`）→ 页面顶部提示「未知的工单状态筛选条件」，并回到全量列表

### E. 照片选错时的退路

分析结果页「待确认」状态下，除「确认 / 修改 / 驳回」外还有次要入口「照片有误？重新上传」，直接回到上传页。

## 四、一句话讲稿

- **AI 只给线索**：结果必须人工确认后才落为结论，AI 失败时不生成任何结果
- **人工是闸门**：确认前不能建单，建单靠人点
- **状态机不可跳步**：待整改 → 待复查 → 已关闭，退回整改可回到待整改
- **全程留痕**：巡检原图、整改说明、整改后照片、复查意见都可回看
- **来源透明**：页面顶部始终标明是演示数据还是真实 AI 分析

## 五、演示失败时的兜底

| 现象 | 处理 |
|---|---|
| 8080 被占用 | `set PORT=9090` 后重启，演示地址同步改端口 |
| 页面 500 | 检查 `data/` 是否可写；重启应用会重新建表 |
| 图片不显示 | 检查 `uploads/` 目录是否存在且可写 |
| AI 分析报错 | `demo` 模式下不会发生；若是 `real` 模式，检查三项 API 配置 |
